## Implemented capabilities

### Canonical bars and multi-timeframe processing

Package: `services/technical_analysis/`

`models.py` introduces a validated OHLCV `Bar` contract with timezone-aware UTC boundaries, instrument, timeframe, source, volume and metadata.

`aggregation.py` provides:

- conversion of I1 IG historical `MarketEvent` BAR events to canonical bars;
- preservation of bid/ask midpoint OHLC metadata and traded volume;
- deterministic tick/event aggregation;
- timeframes M1, M5, M15, M30, H1, H4 and D1;
- deterministic finer-to-coarser resampling;
- OHLCV conservation across timeframe aggregation.

### Deterministic indicators

`indicators.py` implements directly in Python:

- EMA;
- VWAP;
- ATR using Wilder smoothing;
- ADX with +DI and -DI;
- RSI using Wilder smoothing;
- MACD, signal and histogram;
- Bollinger middle, upper and lower bands.

No LLM computes these values. No external TA black box is required by I2.

### Market structure

`structure.py` detects confirmed local swing highs/lows using configurable left/right confirmation windows.

Labels are explicit:

- `HH` — Higher High;
- `HL` — Higher Low;
- `LH` — Lower High;
- `LL` — Lower Low;
- first observations use `SH` / `SL` until comparison is possible.

Structure classification is deterministic:

- `BULLISH` when the last two confirmed highs and lows both rise;
- `BEARISH` when both fall;
- `RANGE` when direction disagrees;
- `UNKNOWN` when confirmed structure is insufficient.

### Pattern engine

`patterns.py` implements seven formal rule families:

1. `BREAKOUT_RETEST`;
2. `FAILED_BREAKOUT`;
3. `PULLBACK`;
4. `SUPPORT_RESISTANCE_REJECTION`;
5. `COMPRESSION_EXPANSION`;
6. `GAP`;
7. `LIQUIDITY_SWEEP`.

Every emitted `PatternSignal` carries:

- pattern name and LONG/SHORT direction;
- timeframe;
- detection timestamp;
- entry reference;
- numeric invalidation level;
- explicit formal preconditions;
- a human-readable invalidation rule;
- machine-readable evidence values;
- lookback used.

The output contract is versioned as `schemas/events/technical.pattern.schema.json`.

### Analysis facade

`engine.py` exposes `TechnicalAnalysisEngine` for single-timeframe and multi-timeframe deterministic analysis. It returns indicators, structure and all detected pattern evidence without invoking ML or an LLM.

## Architecture boundary / non-claims

I2 establishes deterministic technical evidence only.

It does **not** claim:

- I3 market-regime classification;
- I3 deterministic risk-gate controls;
- I4 backtested profitability, expectancy, profit factor or drawdown;
- out-of-sample or walk-forward performance;
- calibrated ML probability;
- agent/LLM authority over indicators or patterns;
- live-money execution.

The pre-existing demo `services/signal_engine/worker.py` remains outside the target I2 implementation. Its arbitrary fractional-price BUY/SELL rule is not considered technical evidence and must be replaced/rewired in a later integration step rather than silently treated as production logic.
